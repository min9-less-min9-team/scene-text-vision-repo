# EDA 정리 (이미지 / 텍스트)

대상: train 6,714 · dev 2,683 · test 6,714 (질문 1개당 이미지 1장, 4지선다).
원본: 이미지 → [`eda/report.md`](../eda/report.md) (`eda/run_eda.py`), 텍스트 → [`eda/text_eda_vqa.ipynb`](../eda/text_eda_vqa.ipynb). 수치는 2026-09-21 실행 기준입니다.

## 한눈에 보기

| 결론 | 근거 | 우리가 할 일 |
|---|---|---|
| **train과 test는 같은 분포**다 | 이미지 지표 \|SMD\| ≤ 0.05, 임베딩 centroid cosine 0.9999, 텍스트 domain classifier AUC 0.501 | train에서 떼어낸 valid 점수를 test 점수의 추정치로 믿어도 된다 |
| **dev는 의도적으로 모호한 문항 집합**이다 | 최다 득표가 3표를 넘는 문항이 0개, 동률 465개(17.3%) | dev 정확도를 절대 수치로 읽지 말 것. 모델 간 상대 비교·어려운 문항 분석용 |
| **train↔test에 같은 이미지가 있다** | 바이트 동일 24쌍 + pHash 동일 6쌍 | valid 분할은 이미지 해시 그룹 단위로. 중복 이미지는 분할 시 한쪽으로 몰기 |

| **정답 보기가 오답보다 평균 1.06자 길다** | 정답 9.68자 vs 오답 평균 8.61자 | 약한 annotation artifact. 보기 셔플 학습 시 길이 단서에 과적합하는지 확인 |
| **세로 사진, 저해상도**가 대부분 | portrait 72%, 중앙값 720×960 (0.69MP) | 입력 해상도를 원본보다 키울 이유가 적다. 작은 글자는 crop이 더 유효할 가능성 |

## 1. 이미지 EDA

**무결성**: 세 split 모두 CSV↔파일 누락/초과 0, 읽기 실패 0.

**크기·방향**: 중앙값 720×960, 평균 0.72MP. portrait 71.8% / landscape 25.1% / square 3.1% (train 기준, test와 TV 거리 0.004).

**픽셀 통계 (train vs test)**: 밝기 0.475 vs 0.472, 대비 0.216 vs 0.218, 채도 0.229 vs 0.229, 엔트로피 7.38 vs 7.39 bit, 에지 밀도 0.130 vs 0.131. 가장 큰 차이가 red_std의 SMD +0.048로, 통상 기준(0.2)보다 한참 작다.

**임베딩 분포** (ResNet-18 ImageNet, 512D): centroid cosine 0.999897, PCA-64 Fréchet 0.0010, RBF MMD² 0.00076. 상위 PC 5개 모두 KS ≤ 0.022. → 시각적 도메인 차이 없음. 단, ResNet-18은 글자 내용을 보지 않으므로 "장면 종류가 같다"는 의미로만 해석한다.

**중복/유사 이미지**
- 바이트 동일(SHA-256) 그룹 45개: train 내부 7, test 내부 7, **train↔test 교차 24**, dev↔test 4, dev↔train 3.
- 교차 24쌍 중 질문 문자열까지 같은 것은 1쌍. 나머지는 같은 이미지에 다른 질문이다 → [`exact_cross_split_pairs.csv`](../eda/tables/exact_cross_split_pairs.csv).
- SHA는 다르지만 pHash 해밍거리 0인 교차 후보 6쌍(재인코딩된 같은 장면으로 추정), train 내부 3쌍, test 내부 4쌍 → [`similar_image_candidates.csv`](../eda/tables/similar_image_candidates.csv).
- 규모가 전체의 0.4% 수준이라 점수에 미치는 영향은 작지만, valid 분할이 이미지 단위가 아니면 같은 이미지가 양쪽에 들어갈 수 있다.

## 2. 텍스트 EDA

**품질**: 결측·빈 문자열·중복 id 없음. dev의 `answer1~5`만 결측이 있다(열당 64~131개).

**길이**

| | 질문 글자수(평균/중앙) | 보기 평균 글자수 | 질문+보기 전체 (p99) |
|---|---|---|---|
| train | 31.8 / 30 | 8.88 | 87.4 (186) |
| test | 31.7 / 30 | 8.85 | 87.1 |
| dev | 35.9 / 35 | 9.65 | — |

train/test는 모든 길이 지표에서 KS ≤ 0.018. dev는 질문이 약 4자 길고 영문·숫자 비율이 조금 높다. 프롬프트 텍스트는 최대 391자로 짧아 토큰 예산은 거의 이미지가 차지한다.

**질문 유형** (정규식 규칙 기반이라 분류 체계에 따라 비율이 달라진다. 노트북 기준)

| 유형 | train % | dev % | test % |
|---|---|---|---|
| 글자 읽기(간판·문구·상호) | 46.5 | 37.5 | 46.1 |
| 대상/종류 | 15.8 | 21.3 | 17.2 |
| 가격 | 13.4 | 14.5 | 12.9 |
| 위치·방향 | 8.9 | 10.7 | 8.8 |
| 전화번호 | 3.3 | 3.4 | 3.1 |
| 색·개수·행동 | 2.4 | 3.3 | 2.3 |
| 기타 | 9.7 | 9.4 | 9.7 |

train/test JS 거리 0.025(거의 동일). `run_eda.py`의 다른 분류 체계에서도 TV 0.015로 같은 결론이다. 과제의 중심은 OCR(글자 읽기 + 가격 + 전화번호 ≈ 63%)이고, dev는 글자 읽기 비중이 낮고 "대상/종류" 비중이 높다.

**보기 구성**: 보기 간 글자 bigram Jaccard 유사도 평균 0.16(세 split 동일). 가격(0.30)·전화번호(0.25) 문항은 보기가 서로 비슷해 한두 글자 차이를 읽어내야 한다. 보기 4개가 모두 숫자·기호로만 된 문항이 train의 약 11.5%다.

**train↔test 텍스트 중복**: 정규화한 질문이 같은 경우 352건(템플릿형 질문: "이 가게의 이름은 무엇인가요?" 등), 질문+보기까지 같은 문제는 1건. split 내부에서도 같은 질문이 600여 건씩 반복된다. 질문 문장 자체는 정보가 거의 없고 이미지가 답을 결정한다.

**텍스트만으로 train/test 구분**: char TF-IDF + 로지스틱 회귀 5-fold AUC 0.501 ± 0.005 → 구분 불가. 반면 train/dev 구분은 AUC 0.626으로, dev는 텍스트 표면형부터 약간 다르다.

## 3. dev 합의도

`eda/common.py`의 `dev_vote_features`로 재계산한 값이며 노트북 결과와 일치한다.

| 최다 득표 수 | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| 문항 수 | 2 | 6 | 649 | 2,026 |

- 평균 응답자 4.84명, 평균 합의율 0.573, 평균 vote entropy 1.20 bit.
- **4표 이상 합의한 문항이 하나도 없다.** 노트북의 전제(train/test는 5명 중 4명 이상 합의한 문항, dev는 그렇지 못한 문항)와 맞아떨어진다.
- 동률 1위 문항이 465개(17.3%). 이 문항들은 "다수결 정답"이 동률 처리 방식에 따라 바뀐다. 실제로 현재 `stv.data`의 다수결(`DataFrame.mode`, 알파벳순 동률 처리)과 먼저 나온 답 우선 방식은 8.4% 문항에서 정답이 다르다.
- 합의도와 텍스트 특성의 상관은 거의 없다(질문 길이와 entropy의 상관 0.08이 최대). 모호함의 원인은 텍스트가 아니라 이미지 쪽(작은 글자, 가림, 여러 간판)일 가능성이 높다.

**dev 점수 사용법 제안**
- 정확도 상한이 구조적으로 낮다(사람 5명도 60% 안팎만 일치). 절대값이 아니라 같은 조건에서의 모델 간 차이로만 본다.
- 동률 465문항은 채점에서 빼거나, 정답을 "해당 보기를 고른 annotator 비율"로 주는 soft 점수를 쓰는 편이 안정적이다(아직 미구현).
- test와 같은 분포의 검증이 필요하면 train에서 떼어낸 valid(`--split valid`)를 쓴다.

## 4. 한계

- 질문 유형은 정규식 휴리스틱이며 두 분석의 분류 체계가 다르다. 유형별 비율은 참고치다.
- 길이는 글자/어절 기준이다. 모델 tokenizer 기준 토큰 수는 재지 않았다.
- 이미지 속 글자의 크기·언어·밀도는 분석하지 않았다(OCR 필요). 해상도 결정에 가장 직접적인 정보라 후속 과제로 남긴다.
- test에는 정답이 없어 정답 분포 비교는 불가능하다.
